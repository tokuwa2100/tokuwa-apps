# 集計表の共有（Firebase）設定手順

集計表アプリ（shukei.html）を複数のPCで同じデータを見ながら使うための設定です。最初に一度だけ行います（15〜20分）。
Firebase の無料プラン（Spark）で使えます。クレジットカードの登録は不要です。

> 画面の文言は Google 側の更新で少し変わることがあります。迷ったら、その画面のスクリーンショットを送ってください。

---

## 1. プロジェクトを作る

1. パソコンで https://console.firebase.google.com を開き、会社で使う Google アカウントでログインします。
2. 「プロジェクトを作成」を押します。
3. 名前は `tokuwa-apps` など分かりやすいもの。
4. 「Google アナリティクス」は **オフ** で大丈夫です。
5. 作成が終わるまで待ちます。

## 2. 集計表用の「ウェブアプリ」を登録する

1. プロジェクトのトップ画面で `</>`（ウェブ）のアイコンを押します。
2. ニックネームは `集計表` 。「Firebase Hosting」は **チェックしない** でください。
3. 「アプリを登録」を押すと、次のような設定が表示されます。**この部分をまるごとコピー**してメモ帳などに保存します。

```js
const firebaseConfig = {
  apiKey: "……",
  authDomain: "……",
  projectId: "……",
  storageBucket: "……",
  messagingSenderId: "……",
  appId: "……"
};
```

（この設定は「どのプロジェクトにつなぐか」の住所のようなもので、パスワードではありません。Claude に送ってもらえれば集計表に組み込み、各PCでの貼り付けを不要にできます。）

## 3. ログイン用のアカウントを作る

1. 左のメニュー「構築」→「Authentication」→「始める」。
2. 「ログイン方法」タブで「メール / パスワード」を選び、**有効にする** → 保存。
3. 「ユーザー」タブ →「ユーザーを追加」。
   - 事務所で使うメールアドレスとパスワードを入れます（例：`office@tokuwa.local` のような社内用の名前でも構いません。実在するアドレスである必要はありません）。
   - 人ごとに分けたい場合は、人数分作ります。
4. **大事：** 「設定」タブ →「ユーザー アクション」で **「作成（登録）を有効にする」のチェックを外して** 保存します。
   （外部の人が勝手にアカウントを作れないようにするためです。）

## 4. データベースを作る

1. 左のメニュー「構築」→「Firestore Database」→「データベースを作成」。
2. 場所（ロケーション）は **asia-northeast1（東京）** を選びます。
3. 「本番環境モード」で作成します。

## 5. 見られる人を決める（セキュリティルール）

1. Firestore Database の「ルール」タブを開きます。
2. 中身をすべて消して、下を貼り付けます。
3. `office@tokuwa.local` の部分を、手順3で作ったメールアドレスに書き換えます（複数あるときは `,` で区切って並べます）。
4. 「公開」を押します。

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isStaff() {
      return request.auth != null
        && request.auth.token.email in ['office@tokuwa.local'];
    }
    match /{document=**} {
      allow read, write: if isStaff();
    }
  }
}
```

あとで人を増やすときは、手順3でユーザーを追加し、このリストにもメールアドレスを足してください。

## 6. 集計表につなぐ（各PC）

1. 集計表を開き、一番上の「☁️ 保存と共有」→「設定を開く」。
2. 手順2でコピーした設定を貼り付けて「共有の設定を保存」。
   （Claude が設定を組み込んだ版では、この手順はありません。）
3. メールアドレスとパスワードでログインします。
4. 右上の表示が **🟢 リアルタイム共有中** になれば完了です。
5. 「担当者名」に自分の名前を入れておくと、修正の履歴に名前が残ります。

### 今までこのPCに保存していた日報がある場合

ログイン後に「このPCに、共有前に保存した日報が○件あります」と出ます。「共有へ送る」を押すと共有に移ります（登録済みのものは飛ばします）。作業確認書も一緒に移ります。

---

## 使い方のメモ

- **日報の登録**：現場から届いた日報の画像を、どのPCの集計表に入れても全PCに出ます。同じ日報を2回入れても二重になりません。
- **修正**：「🔎 日報を探す」で日報を開き「✏️ 修正する」。原本（現場から届いた内容）はそのまま残り、誰がいつ何を直したかが履歴に残ります。集計表・Excel・作業確認書は修正後の数字で計算します。
- **同時に直したとき**：あとから保存した方は止まり、「ほかのPCで先に修正されました」と出ます。先の修正は消えません。開き直してから直してください。
- **修正版の画像**：日報を開いて「🖼 画像を出す（修正版）」で、「修正版」の印が付いたB5画像（QRも修正後の内容）を作れます。原本の画像をもう一度読み込んでも、修正は上書きされません。
- **インターネットが切れたとき**：表示・検索・集計はできます。登録・修正・作業確認書の発行は、つながってから行ってください（番号の重なりや修正の取り違えを防ぐため）。
- **古い日報**：起動時は直近約13か月分を読み込みます。それより前は、検索で期間を指定したときに読み込みます。
