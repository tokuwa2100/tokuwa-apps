# 日報のGoogleドライブ保存　設定手順

現場のスマホ（日報アプリ）から、会社のGoogleドライブへ日報を直接保存するための設定です。最初に一度だけ行います（15分ほど）。

> 画面の文言は Google 側の更新で少し変わることがあります。迷ったら、その画面のスクリーンショットを送ってください。

---

## 1. Apps Script のプロジェクトを作る

1. パソコンで https://script.google.com を開き、**日報を保存したいGoogleアカウント**（会社のアカウント）でログインします。
2. 左上の「新しいプロジェクト」を押します。
3. 左上の「無題のプロジェクト」を押して、名前を `徳和 日報受け口` にします。
4. 最初から入っている `function myFunction() { … }` を**すべて消し**、`nippo-drive.gs` の中身を**まるごと貼り付け**ます。
5. 上の 💾（保存）を押します。

## 2. 合言葉を2つ決めて登録する

合言葉はコードには書かず、ここだけに登録します（公開されているアプリのコードから見られないようにするため）。

| 名前 | 使う場所 | できること |
|---|---|---|
| `WORKER_KEY` | 作業員のスマホ（日報アプリ） | 日報を送ることだけ |
| `OFFICE_KEY` | 事務所の集計表 | 日報の取り込み・修正の反映 |

- 2つは**別の言葉**にしてください。8文字以上、推測されにくいものがおすすめです（例：`tokuwa-genba-2026` のような言葉＋数字）。
- 作業員が辞めたときなどは `WORKER_KEY` を変えれば、古い合言葉では送れなくなります（その場合は全員のスマホで入れ直し）。

1. 左のメニューの ⚙（プロジェクトの設定）を押します。
2. 一番下の「スクリプト プロパティ」→「スクリプト プロパティを追加」。
3. プロパティ `WORKER_KEY`・値に作業員用の合言葉 → もう1行追加して `OFFICE_KEY`・値に事務所用の合言葉。
4. 「スクリプト プロパティを保存」。

## 3. 動作確認（ドライブの使用を許可する）

1. 左のメニューの `<>`（エディタ）に戻ります。
2. 上の関数の選択欄で `setupCheck` を選び、「実行」を押します。
3. 「承認が必要です」→「権限を確認」→ アカウントを選びます。
4. 「Google はこのアプリを確認していません」と出たら、「詳細」→「徳和 日報受け口（安全ではないページ）に移動」→「許可」。
   （自分で作ったスクリプトなので問題ありません）
5. 下の「実行ログ」に、フォルダと台帳のURL、`WORKER_KEY: 登録済み`・`OFFICE_KEY: 登録済み` が出れば成功です。
   ドライブに **「日報（アプリ）」フォルダ** と、その中に **「日報台帳」**（スプレッドシート）ができています。

## 4. 公開する（受け口のURLを作る）

1. 右上の「デプロイ」→「新しいデプロイ」。
2. 左の ⚙ で種類「ウェブアプリ」を選びます。
3. 説明：`日報受け口`
   次のユーザーとして実行：**自分**
   アクセスできるユーザー：**全員**
4. 「デプロイ」を押します。
5. 表示される「ウェブアプリ」のURL（`https://script.google.com/macros/s/……/exec`）をコピーして、**Claude に送ってください**。アプリに組み込みます。
   （URLだけでは日報は送れません。合言葉が必要です）

### あとでスクリプトを直したとき

「デプロイ」→「デプロイを管理」→ 鉛筆マーク →「バージョン」で「新バージョン」→「デプロイ」。
こうすると**URLは変わりません**（「新しいデプロイ」を作るとURLが変わるので注意）。

---

## 5. アプリ側の設定

- **作業員のスマホ**：コア日報・常用日報アプリの入力画面の一番下「⚙ ドライブ送信の設定」に `WORKER_KEY` の合言葉を入れて「保存」（アプリごとに1回）。
- **事務所のPC**：集計表の「☁ Googleドライブの日報」→「ドライブ連携の設定」に `OFFICE_KEY` の合言葉を入れて「保存」（PCごとに1回）。

---

## 使い方のメモ

- **送信**：日報アプリで「保存（提出）」を押すと、自動でドライブへ送ります。電波が無いときはスマホに残り、つながったとき（またはアプリを開いたとき）に自動で送ります。上に「ドライブ未送信の日報」の赤い帯が出ている間は、まだ届いていません。
- **LINE送信**：予備として残しています。LINEで送っても、ドライブ送信は別に行われます（二重にはなりません）。
- **保存場所**：`日報（アプリ）/2026/2026-10/2026-10-30/` のように**作業日**ごと。画像（.png）とデータ（.json）が並びます。取引先ごとのフォルダは作りません（取引先名はデータの中に入っています）。
- **集計表への取り込み**：集計表を開いている間、5分ごとに自動でドライブを確認します。すぐ取り込みたいときは「ドライブから今すぐ取り込む」。
- **集計表で直したとき**：修正・削除・繰越の設定は、ドライブのデータ（.json）にも反映します。作業日を直すとフォルダを移し、取引先名・現場名を直すとファイル名も直します。現場で署名された画像（.png）は原本としてそのまま残し、最初の修正のときに `_原本.json` も残します。削除した日報はファイル名の先頭に `【削除】` が付きます。
- **日報台帳**：届いた日報が1行ずつ並ぶ一覧です。見るだけにして、**手で書き換えないでください**（集計表との対応が崩れます）。

## 取引先と締め日（集計表）

- **締め日一覧**：取引先ごとのいつもの締め日（月末・○日締め）。全PCで共有します。
- **月ごとの締め日変更**：ある月だけ締め日より前（またはあと）に締めたときは、その取引先の「月ごとの締め日変更」に入れます。次の月の期間も自動でずれます（例：15日締めの取引先が11月分を11/12で締めた → 11月分は10/16〜11/12、12月分は11/13〜12/15）。
- **繰越**：日報1件ずつ「◀ 前月分へ」「翌月分へ ▶」で請求月を動かせます（集計表の下の「この期間の日報」、または日報の修正画面の「請求月（繰越）」）。修正の履歴に残ります。
- **取引先名の表記ゆれ**：「㈱」「株式会社」「（株）」・空白の違いは同じ取引先として扱い、取り込むときに正式名へ直します。一覧に当たらない名前は「取引先と締め日」に表示されるので、「まとめる」（同じ会社）か「新しく登録」を選んでください。
